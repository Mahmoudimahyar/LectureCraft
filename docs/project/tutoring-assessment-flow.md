# Submitted explanation → grounded assessment → next conversation

Revision 0.6.0, proposed. This uses existing catalogs and canonical observations, not a new gap
ledger. All actual submissions are captured, but canonical assessment publication can remain
blocked when valid family/criteria or writer permissions are absent.

1. On deliberate submission, commit full prompt, learner response, required figures/attachments,
   assistance/exposure and occurrence-time basis. Validate/read back the immutable sidecar before
   inference. An edited answer is a new revision/event, not replacement bytes.
2. Resolve the existing question/family/version and target skills. Select the relevant source spans
   and catalog neighborhood. A graph display is a projection; its absence is system coverage, not
   lack of learner knowledge. Load actual course strategy/assistance instructions explicitly.
3. Use the existing rubric, or first prepare a source-grounded provisional rubric for review.
   Generated reference answers are not instructor keys. Assess valid alternatives and uncertainty;
   do not invent required criteria merely to fit the response.
4. Produce exactly the intended skill observations: outcome, assistance, reference access, analysis,
   missing_or_incorrect, error_types and confidence under the current schema. Do not diagnose an
   unobserved skill. Separate speech-recognition ambiguity, procedural slips and possible tutor error.
5. Propose a discriminating follow-up only when useful. Until the learner actually replies, WAITING_USER
   ends the current runnable unit; the tutor must not answer on their behalf or recurse indefinitely.
   Hypotheses live as operational proposals and do not independently redefine learner ability.
6. The wrapper verifies full-sidecar and candidate identity; the appropriate writer then performs
   canonical validation, exclusive publication/readback, and controlled view generation. Preserve
   saved-versus-staged-versus-stale distinctions. No installed BE 505 writer is tested via a fake root.
7. Return what was correct, what was missing, a grounded explanation and an optional next action.
   Store this exact user-visible tutor reply as another message linked to the frozen input and run.
   Do not persist hidden model deliberation. Full prompt/response/answer remains navigable.
8. WF10 rebuilds the gap view from effective assessments, including date, assistance, source/rubric
   provenance and original attempt IDs. A later assessed answer can change the evidence; a corrected
   judgment uses the existing revision chain. Time elapsed or a prerequisite edge does not imply failure.

The old record validator checks nonempty response locators but not sidecar content; the wrapper's
checks are a required new integration seam. A canonical attempt and its sidecar can survive a view
failure; retry only after inspecting the exact receipt/state. No second assessment when the native
provider repeats a message. See [full-turn contract](full-turn-snapshot-contract.md).
