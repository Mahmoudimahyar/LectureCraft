# Implementation decisions and deviations (application 0.1.0-alpha.1 on baseline 0.9.0)

This records material choices made while implementing the 38 local task facets, with their rationale.
It does not change any frozen acceptance criterion, requirement, story or gate; where the
implementation falls short of a specified behaviour, the shortfall is listed under **Known limits**
and stays an open item. All-lecture scope is unchanged: the coverage denominator is every lecture
unit of all five configured courses and cannot be filtered.

## Decisions

| # | Decision | Rationale | Where |
|---|---|---|---|
| D1 | **Three profiles.** `fixture` (generated synthetic workspace, labeled test-double tutor, writes into its own synthetic roots), `local` (real roots read-only, every write staged under the local state directory), `live` (requires bound, approved writers and a verified native target). | Lets the whole product run and be tested without touching a real course, while the real-root code paths are the same readers. | `brain/src/lecture_brain/config.py` |
| D2 | **Local transport is file-shaped.** The browser uploads the same immutable, signed bundle files to the loopback Brain that it would place in Drive; the Brain admits only complete bundles. A Drive transport (GIS token client + Drive v3) is implemented and not activated. | One protocol for both paths; no private PC port is ever exposed off loopback; Drive needs the owner's OAuth client and consent. | `web/src/lib/transport.ts`, `brain/…/transport/` |
| D3 | **Device identity** is a non-extractable P-256 WebCrypto key; signatures are `ES256-P1363` over `LL-BUNDLE-V1\n<manifest sha256>`. Pairing is approved at the Brain PC after comparing fingerprints. | Standard primitives in both runtimes; a request can never enrol or approve its own key. | `web/src/lib/device.ts`, `brain/…/transport/signing.py` |
| D4 | **Request identity is scoped to device and sitting.** `request_id`/`logical_input_id` = hash(device id, browser session id, action, draft key, text). | A double click or an immediate retry is one request; another device, or the same words on another day, is a new request. (Before this, two devices sending identical text collided.) | `web/src/lib/requests.ts` |
| D5 | **Attempt id** = `<course>-ll-<sha256(logical_input_id)[:20]>`; an assessment revision id = `<course>-ll-rev-<sha256(request_id)[:20]>`. | Deterministic, so an interrupted commit resumes with the same candidate bytes and the owner's "same id, same bytes" rule gives exactly-once. | `brain/…/coordinator.py` |
| D6 | **Mapping to the owners' vocabulary.** Interaction → `mode`: review answer → `maintain`; otherwise `assess` when no help was reported, else `learn`. Help: `none_reported→none`, `hint→hint`, `formula→formula_provided`, `worked_solution→solution_shown`, `unknown→unknown`. References: `none_reported→none`, `sources/notes→notes`, `unknown→unknown`. Prior exposure: `unseen_reported→unseen`, `seen_question/seen_solution→seen_exact`, `unknown→unknown`. Time: `recorded_now` only when the device time is within 15 minutes before the Brain records it; otherwise `occurred_at: null` with the device value kept in the capture sidecar. | Reuses the existing `course-learning-v1` fields instead of adding a parallel schema; quick/understand/explain depth stays UI metadata. All conditions are self-reported and labeled so. | `brain/…/writer/candidate.py` |
| D7 | **`question_version` comes from the course's question index** (default 1 only when a course has no index). | The owner's save helper refuses a mismatching version. Found by running a copy of that helper on synthetic roots. | `brain/…/tutoring/context.py` |
| D8 | **Full-turn capture** lives beside the owner's run evidence: `.agent/course-learning/runs/ll-<session>/{turns,messages,attachments,receipts,proposals,context}`; the attempt's `response_evidence.locator` points at the frozen submission with its digest. App-owned operational data lives under `.agent/learning-app/`. With writes disabled everything goes to `<state>/shadow/<course>/`. | Keeps one canonical attempt record (the owner's) and adds only referenced sidecars. | `brain/…/capture.py`, `config.py` |
| D9 | **BE 505 save helper is wrapped, never imported**, and only for the course root it lives in (its `--root` flag does not redirect writes). An existing record is decided by bytes without starting the helper. | The helper's identical-retry path regenerates derived files and can fail after the record is safe. | `brain/…/writer/__init__.py`, `tools/isolated_writer_check.py` |
| D10 | **Slide↔recording matcher** = TF-IDF similarity with a monotone dynamic programme over transcript lines; every output is a *suggestion* until the learner confirms it. | Deterministic, no model download, no inference cost; quality on real lectures is unmeasured and stays a live gate. | `brain/…/preparation.py` |
| D11 | **Review scheduling** uses py-fsrs 6 (fuzz off, desired retention 0.9) replayed from immutable review events; a hinted or ungraded review is "practice only" and feeds no rating. | Maintained library; schedule is always derivable from events. | `brain/…/review.py` |
| D12 | **Study priority** on the Progress screen is saved as the learner's note; the course's skills catalog and requirements are not edited. | The catalog is owned by the course; the app has no reviewed writer for it. | `web/src/features/progress/` |
| D13 | **Cleanup removes only rebuildable data and queues its rebuild.** | Otherwise removed slide text silently dropped out of search (found by the browser suite). | `brain/…/runtime.py` |
| D14 | **Browser suite retries once**; any test that needed the retry is reported as flaky, never as a plain pass. | Long runs on Windows occasionally hit loopback socket exhaustion (`net::ERR_NO_BUFFER_SPACE`). | `web/playwright.config.ts` |
| D15 | **Storybook without addons**, built to ignored `.local/`, and every story is rendered and accessibility-checked in both themes by the browser suite. | Component states become checked behaviour instead of screenshots; no extra plugins. | `web/.storybook`, `web/e2e/stories/` |
| D17 | **A corrected capture is linked evidence on the same attempt.** A submission carrying `supersedes_capture` is frozen as new evidence; when the original capture belongs to a saved attempt, that attempt is re-read against the corrected wording for the same skills — a changed outcome becomes one linked `assessment_revision` (reason starts "Capture correction"), an unchanged one writes nothing. The original snapshot and attempt are never edited and no second attempt is created. | A transcription mistake is neither a plain regrade nor new knowledge evidence (UXAC100, LL027). | `brain/…/coordinator.py` (`_capture_correction`), `web/src/features/tutor/RequestCard.tsx` |
| D18 | **Retained requests are sent automatically, once.** A signed request that could not be delivered stays in the device outbox and is handed over whenever the Brain answers again (each successful workspace refresh), or by "Send now"; both paths share one single-flight run and never rebuild or re-sign the bundle. | The app promises "sent when the Brain is reachable"; before this only the manual button did it (found when a browser test reloaded mid-upload). | `web/src/lib/requests.ts`, `web/src/app/state.tsx` |
| D19 | **Private state for real courses is pinned in the workspace.** `config/local-bindings/workspace.json` may set `local_state_dir` (relative paths are anchored in the repository); a location inside a course or planner folder is refused. | Derived files for real courses (prepared slide text, suggestions, hash cache, journal) must be private, local and never inside an owner's folder. | `brain/…/config.py` |
| D20 | **Files the course index has not registered are identified by content** (`disk-<sha256[:12]>`), hashed once per file version and cached. A cited source whose bytes no longer match is not used as tutor context, and a link naming non-current bytes is refused. | On the real courses most decks and recordings are unregistered; without an identity a slide could not be cited, noted or linked. Exact-version citation must not degrade into "whatever the file says today". | `brain/…/preparation.py`, `tutoring/context.py`, `annotations.py`, `projections.py` |
| D21 | **A lecture unit may hold several files.** The unit is shown with its first displayable deck (a readable PDF; registered before unregistered); every other file of the unit is listed in the lecture's Sources pane and opens as its original. Only the main deck is prepared for search and slide links. | Real units hold several papers, an occasional empty placeholder, or a PowerPoint beside its PDF; showing only the first file by name hid the rest. | `brain/…/ownerio/inventory.py`, `web/src/features/lecture/SourcesPanel.tsx` |
| D22 | **The learner can create a slide↔recording link.** When nothing is suggested (untimed transcripts — the normal case in the real courses), "Link this slide to the recording" records a revision-1 annotation confirmed by the learner, with typed times bounded by the recording length (read from WAV and m4a/mp4 headers) and the recording file cited as support. | Without it the per-slide recording feature was unusable on real material; nothing is inferred automatically. | `web/src/features/lecture/`, `brain/…/annotations.py` |
| D23 | **A question without wording in the index gets a pointer, not a paraphrase.** Where the course index keeps `prompt: null` and marks the original page as authoritative, readers receive a stand-in that names the original file and page (`prompt_in_index: false`); assessment supplies that page (never a solutions file) to the tutor. | Such entries made the real BE 505 search index fail and could not be practised. Inventing wording would violate the owner's rule that the original is authoritative. | `brain/…/ownerio/catalogs.py`, `tutoring/context.py`, `web/src/features/question/` |
| D24 | **The fixture profile runs only on a generated synthetic workspace.** It writes directly and answers with a labeled keyword double, so it refuses any planner/course folder that does not sit under the generator's marker file. Real folders are opened only by `local` (read-only, staged) or `live`. | The test tutor must never meet real data, whatever a caller, a file or the environment says. | `config.py`, `test_boundaries.py` |
| D25 | **A path is followed only inside its course folder.** An index entry whose path leaves the course, or a folder reached through a symlink/junction that leads out, is reported (`registered_path_outside_course`, `skipped_outside_course`) and never read, hashed, prepared or served. | The course index is the owner's, but it is data; a wrong or hostile path must not widen what the app reads. | `ownerio/inventory.py`, `api.py`, `test_boundaries.py` |
| D26 | **Loopback is not authentication.** A request must come from the app's own origin (same host and port); lookalike hosts, other local ports, sandboxed documents (`Origin: null`) and cross-site fetches are refused. This tightened an earlier rule that accepted any loopback origin. | Another local page or a course document must not drive the Brain or read private evidence from it. | `api.py`, `test_api.py`, `test_boundaries.py` |
| D27 | **Every turn this app starts runs in a restricted native scope that is read back first.** The app-server child is launched with per-process overrides (read-only sandbox, approval never, no tool servers, plugins, hooks, shell, web search, memories or notify program, no instruction files); the effective configuration is read from the running process and an unsafe scope blocks (`unsafe_scope`) instead of sending. Approval wire values follow the installed binary's generated schema (`untrusted` / `on-request` / `never`). | The user's own Codex default is full access with tool servers; an unattended tutor turn must not inherit it. Launch arguments are not evidence of the effective scope. | `native/codex_app_server.py`, `test_native.py` |
| D28 | **The single-request proof is a separate record that cannot enable tutoring.** `probe-native --disposable` creates a new disposable thread, sends exactly one synthetic request, never re-sends, classifies the result (`SEPARATE_WORKER_ONLY` at best) and stores it apart from the adapter proof; no adapter becomes selectable from it. | One success shows a worker can round-trip; it does not show desktop-thread continuity or authorize course dispatch. | `native/disposable_proof.py`, `maintenance.py` |
| D29 | **Preparation and search cover the whole inventory.** Every further readable PDF of a unit is prepared privately (keyed to its bytes) and searchable by page; transcripts of sessions the index links to no lecture are searchable by line and open as sources, never inside a guessed lecture. Slide-to-recording links remain for a unit's main deck only. | All supported material is the learner's, not only the first file of a unit. | `preparation.py` (`prep-3`), `projections.py`, `search.ts` |
| D30 | **The matcher test asserts mechanics, not a tuned accuracy.** An earlier version carried a 0.85 line-accuracy threshold that let a missed revisit pass under a name claiming revisit recovery. The threshold is gone; the missed weakly-worded revisit is a strict expected failure. QT04 (95% precision on at least 100 adjudicated real cases) stays unmeasured. | A test must state intended behaviour; a loosened number is not a quality claim. | `test_preparation.py` |
| D31 | **Evaluation keeps hard case kinds apart and has an offline mode.** Valid alternative, partial, unclear transcript, unasked prerequisite, assisted answer, disputed grade and unmatched source are reported separately; disputed labels are excluded from agreement until adjudicated. `evaluate --scripted` replays replies written in the case file (labeled double). Cases drafted by a developer or model carry `drafted_unreviewed` and can never promote. | One blended agreement figure hides exactly the failures that matter; drafts are neither synthetic nor reviewed. | `evaluation.py`, `fixtures/evaluation/case-kinds.json` |
| D32 | **PowerPoint is not automated as a converter.** Microsoft PowerPoint is installed on this PC, but the approved converter in the component selection is LibreOffice in an isolated process; driving the user's Office application was not added without that decision. The adapter stays implemented and tested; the status is shown in Settings. | Changing the approved component silently would be a scope decision, not a repair. | `preparation.py`, `maintenance.py` |
| D33 | **Native continuity is proven once, on the existing disposable thread, and reported as separate answers.** `probe-native --continuity` resumes the exact thread of the single-request proof from a new restricted client process, verifies scope and thread before each turn, sends at most two synthetic turns ever (marker set, then asked for after a reconnect without being resupplied), never re-sends, never creates a thread, and stores its record apart. It reports process roundtrip, resumed-thread history, terminal retrieval, desktop visibility, desktop-thread control, course-context loading and production activation separately. | A remembered marker shows thread history for a worker-created thread; it shows nothing about the desktop app, course instructions or readiness to tutor. One verdict would overstate it. | `native/continuity_proof.py`, `test_native.py` |
| D34 | **A revisit announced in words is its own kind of evidence.** The matcher offers a second occurrence of an earlier slide when a line says "slide", uses a back-pointing word and names a title word of exactly one earlier slide; the revisit lasts while the following lines still relate to that slide. Every segment now states its `basis` (`similarity` or `title_reference`). Thresholds for wording-only matches are unchanged. | The known defect was a weakly worded revisit swallowed by the last section. A first, looser form of the rule produced mostly false revisits on real lectures and was tightened; on real lectures the final rule fires 0 times, so real revisit detection stays unverified. | `preparation.py` (`prep-5`), `test_preparation.py` |
| D35 | **Identities derived for unregistered files are provisional and say so.** `unreg-…` ids and `disk-…` versions are labelled provisional on source pages and in exported links, never appear in course-owned attempt records, and are not presented as course source ids. Re-keying links when the course registers a file is not built. | 42 of 61 decks and 27 of 30 recordings are not in the course index; the app must use them without minting canonical ids silently. | `ownerio/inventory.py`, `api.py`, `annotations.py`, `test_boundaries.py` |
| D36 | **A case file is "reviewed" only case by case.** `label_source: reviewed` is refused unless every case carries a review record with status `reviewed`, a named reviewer who is not the drafting assistant, and a date. | Drafted labels must not become reviewed labels by editing one word. | `evaluation.py`, `test_ops.py` |
| D37 | **The course-tutor pilot is its own profile (`pilot`), labelled "Experimental Codex worker tutor".** It routes allow-listed courses to a restricted, app-created Codex worker under a written grant: one thread, a fixed number of turns, a slot reserved on disk before each send (an unclear acceptance has used its slot; a dispatch is never sent twice; a restart cannot forget; more than four turns is refused even if a file asks for it). Scope is read back before every turn. Course writes cannot be enabled in this profile. The `local` profile's guards are unchanged, and the pilot's state folder may not be the `local` one. | A trial route chosen by the owner for one pilot. It is not the desktop course chats, never replaces them silently, and nothing falls back to or from it; desktop-thread integration stays unresolved. | `config.py`, `native/pilot.py`, `native/__init__.py`, `test_pilot.py` |
| D38 | **What the pilot worker is given is limited and written down.** Only the course's own `AGENTS.md` and the cited source span are supplied; learner history, answer guidance, `learning-strategy.md` (speaks about the learner's attempts) and the planner's tutoring policy (names the learner, planner preferences) are withheld by rule. Each request gets a context manifest (instruction files and source spans by version and hash, text sizes and digests, the prompt digest, the effective scope) and the exact prompt is kept privately. | The owner allowed course policy, one small excerpt and source metadata, and excluded learner history, grades, restricted keys and personal planner data. Withholding the tutoring policy means tone and pacing rules are not exercised in the pilot. | `tutoring/context.py`, `native/pilot.py` |
| D39 | **A pilot assessment records nothing.** It judges synthetic test responses: the feedback is delivered to the browser, but no attempt candidate is built, staged or stored — not in the course, not in the pilot's own store or journal — and the request finishes instead of waiting for a save. The first real pilot run predates this rule's enforcement in the coordinator and left one candidate file inside the pilot's private store; it was found by inspection, reported, and the gap closed test-first. | "Not recorded" must be literally true, including in private storage, so synthetic material can never be mistaken for the learner's evidence later. | `coordinator.py`, `writer/__init__.py`, `test_pilot.py` |
| D16 | **Candidate label.** The packaging tool labels a build `integration-blocked-candidate` while any original gate is uncleared, and at most `release-candidate-awaiting-approval`. | A local build cannot approve itself. | `tools/package_candidate.py` |

## Known limits (open, not waived)

- **Spoken teach-back has no automatic transcription.** Recording is local-only and the learner types or corrects the
  transcript; no speech model is installed and no online speech service is used (`LOCAL_MODEL_INSTALL`, `MICROPHONE`
  gates). The text path and the "microphone refused" path are implemented and tested.
- **Assessment quality is unmeasured.** The evaluation harness runs; the bundled cases are synthetic and exercise mechanics
  only. Real reviewed labels and an authorised model run are required (`EVALUATION_RUNS`).
- **Slide-to-recording links exist only for a unit's main deck.** Further PDFs of a unit are prepared and searchable by page (D29) but cannot yet be linked to the recording slide by slide.
- **No automatic recording-time alignment exists for the real lectures.** All 30 real transcripts are untimed, so the matcher offers transcript-line suggestions only; a link made by hand while listening is an interim workaround, not completed alignment. Revisit detection on real lectures is unverified.
- **Pipeline suggestions are not retired when the matcher changes.** After a matcher change the private suggestion store is rebuilt by hand; reviewed links are unaffected.
- **Desktop-thread control is not established.** Three synthetic turns ran through a separate restricted worker on one disposable thread, with thread history kept across a reconnect. Whether the desktop app shows that thread is unconfirmed, and no desktop-created thread was resumed or driven (the shared daemon's control socket was unreachable). Course instructions were never sent to the real runtime.
- **The pilot worker is not the product's native route.** Three pilot turns (two quick answers, one synthetic assessment) ran through the browser app to a restricted Codex worker for BE 505. That is evidence about this worker path only; answer quality was read, not measured, and the worker tutored without the tutoring policy.
- **PPTX decks** are listed as "needs a PDF rendition"; conversion needs LibreOffice, which is not installed. Nothing is
  regenerated in their place.
- **Native tutor**: the app-server adapter is a candidate tested against a labeled local double of the protocol; it has
  never contacted a real thread (`NATIVE_PROBE`).
- **Drive, static hosting, a second physical device, live course writes, processing of the real archive**: prepared in
  code, not performed (`DRIVE_OAUTH`, `STATIC_DEPLOYMENT`, `DEVICE_PAIRING`, `DEVICE_ACCEPTANCE`, `LIVE_WRITE`,
  `PREPARATION_EXECUTION`).
- **Seed foundation**: the upstream archive was not available; its tools and tests are not bundled or claimed.

### R2 — open after this amendment (not waived)

Recording these requirements does not close them. Until the named evidence exists, each of the following is an open item, whatever a board or receipt says:

- **Visual design:** not accepted. At best "designer-reviewed" after R2-V10; the learner's approval is theirs to give.
- **Timing:** acoustic accuracy of generated timestamps is unreviewed; association quality is unmeasured against adjudicated real references (QT04, QT05); coverage beyond what the four-hour allowance reaches is backlog, shown as backlog.
- **Slide identity and roles:** inferred groupings and roles are suggestions until reviewed; a deck without a PowerPoint source has no recoverable PowerPoint numbering.
- **Question links:** inferred anchors are suggestions, checked by a second agent pass at most; a question without one says so with its recorded reason. Whether a question was examined without any candidate cannot be recorded in the fixed file format; restoring that distinction needs a decision on the format.
- **Evidence for every check:** none of the R2 checks has runtime evidence from this amendment; each stays open until its on-screen row has been observed on a recorded build.
- **Concept maps:** discoverability is judged by ordinary navigation in a real browser; evidence views add no assessment the records do not contain.
- **Live gates:** native tutoring, course writes, Drive, a second device, scheduling and evaluation with reviewed labels are untouched by R2 and remain uncleared.
