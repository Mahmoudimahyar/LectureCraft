# Small interface probes, full all-lecture product scope

Status: plans only. Uploading the audit authorizes no dispatch, host provisioning, source
publication, repair or real learner record. The probes require exact scope/permission approval
before execution; existing scheduled jobs and guards must not be weakened to make them pass.

## P1 — Actual ChatGPT identity and roundtrip

Record the exact requested product/surface/project/session and distinguish it from each Codex
project in P05. Use a synthetic one-line source and disposable request in an approved entry point.
Demonstrate request identity, actual native message delivery, usable context and returned result
identity to staging. Exercise denial, closed/unavailable session, duplicate submit, timeout,
cancel/late result and wrong-course refusal. Verify authentication and billing mode without
extracting credentials. A native tool call from inside Codex is not by itself this test passing.

Candidate embedded UI and standalone bridge are evaluated separately. Choosing an embedded
prototype does not silently decide final UI placement or prove background invocation to an
arbitrary old conversation. Do not send work or create a synthetic learning attempt merely to
produce a result. Expected artifact: capability record with observed steps, evidence and unknowns.

## P2 — Portable Drive access and playback

From an approved second device, resolve one authorized text file, slide source and original
recording by canonical source/Drive identities, not G:. Test permission denial, current revision,
actual playback/seek, large-file retrieval/token refresh and returning to the slide. Do not
claim all-device performance from a small text read or store transient download URLs as identity.
If using hosted processing, approve host/access/retention before moving course data.

## P3 — Layered alignment

Use existing BE 505 L02/L04/L06 reviewed maps as seed associations and permitted segments with
actual media. Check whether TXT is verbatim/edited/partial, establish transcript-time evidence,
then match slides. Include skipped/revisited slides, a truncated recording, a PPTX source and
any video whose screen content is actually established. Log reference times, boundary errors,
unsupported matches and correction work. Use no fabricated times for BE 562's reported unrecorded
lecture or BE 572's empty PDF. Failures are inventory exceptions, not permission to drop lectures.

After a method passes bounded tests, evaluate/apply it across every configured lecture and new
arrival. Track overall coverage, precision and missing inputs separately. No small-sample pass
licenses a perfect whole-archive claim. Accuracy/latency tolerances await reviewed real examples.

## P4 — Course-learning writer on isolated fixtures

Acquire the actual current schemas and helper files; do not implement a writer from projected
JSON snippets. First test the reported global-root issue using two fixture roots and instrumentation
that blocks live-course access. Test exact candidate validation, identical retry, conflicting ID,
view-generation failure, known assistance and a synthetic assessment-revision chain. Preserve
original response and old assessment. Record canonical record receipt separately from current
view output. For tracking repairs, use its different contract and test requested source hashing
against changed source bytes. No unapproved production write or full-history reset.

## P5 — Chosen laptop-off behavior

With the authorized deployment, submit a synthetic response, disconnect the primary machine,
and observe permitted reading, engine access, durable queuing or canonical save as selected by
the user. Reconnect, reconcile by IDs and ensure no duplicate record or stale overwrite. Do not
call durable response staging 'saved progress' until the course writer confirms it. Migrate or
coordinate all participating writers before claiming an always-on multi-device publication path.

## Separate release acceptance

- All configured courses, 37 reported lecture units, 31 session folders and subsequent arrivals
  are accounted for in the inventory; actual present/missing/empty/unindexed states are visible.
- Each supported source format has correct identity/rendition behavior; genuine unresolved links
  and absent media are surfaced, not invented. Exact matching quality must be evidenced.
- The requested ChatGPT route actually works across approved devices; no Codex or billed-API
  substitution. A read-only demo is not the complete tutor.
- Original responses, immutable attempts, assistance, course policies and separate writers retain
  their meaning. Wrong assessment can be disputed without rewriting raw learner evidence.
- Review, questioning and later independent performance are evaluated separately from technical
  source navigation and save mechanics. No schema pass proves teaching accuracy.
- Required tests implement intended behavior using incremental TDD; actual result logs remain
  outside approval-bound specs. Build approval applies to the agreed revision, not these drafts.

These probes do not implicitly narrow the first release to one course or three lectures.
