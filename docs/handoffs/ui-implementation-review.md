# Handoff: implement the scoped UI/story baseline

Read current README, docs/project/ui-decisions.md and the shared state contract. Choose the approved
feature; then read its requirements.md, ui-flow.md, test-plan.md and plan.md plus linked memory and
workflow contracts. Do not consume the entire historical research corpus on every task.

Use the stable story/requirement IDs in experience-spec.json. Start one meaningful test before the
smallest implementation and reuse maintained primitives. Keep original source, existing catalogs,
attempts/corrections and appropriate writers authoritative. Full capture and job state do not become
a second learning schema. Mock data must be visibly synthetic and cannot satisfy live acceptance.

Verify light/dark/system, narrow screens, keyboard/focus, source-fidelity, saved drafts and the real
error paths—not just the screenshot. Current native/Drive/writer boundaries stay blocked until actual
approved tests pass. No install, service startup, account changes, API spending or course writes are
permitted merely by this document. Scope approval and results must be recorded through the actual
Seed app project once adopted; this discovery packet is not that initialized application repository.
