# Change reconciliation — 2026-10-03

User clarification resolves primary host placement: always-on PC with native Codex/course projects.
It does not verify a generic ChatGPT Markdown event hook. The latest design no longer asks the user
to decide laptop-off canonical writer hosting. It retains unexpected outage handling.

The user explicitly expands new submitted app-learning capture to full questions, responses,
concept-linked gap observations and dates. The previous system stores excerpts in immutable
attempts and is not a passive whole-chat recorder. New full episode files/sidecar references are
proposed, with actual schemas still authoritative. Earlier attempts are not backfilled with
invented text. Every submission is retained even when assessment is blocked; browsing/Ask alone
is not automatically a skill failure. Hidden reasoning is not part of full visible Q/A history.

Dedicated agents become logical named workflow contracts and queues coordinated by ordinary code.
The design includes 12 workflows and 40 proposed acceptance scenarios; neither count is a claim of
deployed agents or tests run. All lectures remain in the processing frontier across bounded batches;
waiting/unknown media is not marked matched. There is no endless LLM polling, model committee,
automatic self-improvement, unauthorized paid API, new cron job or public server.

Current source audit facts are attributed to the managing agent's October 2 report. Primary
external documentation was rechecked for dispatch, auth, Drive changes and local queue storage.
Actual interface tests remain NOT_RUN. Current principal docs and the decision register have been
updated; historical ADR/research/audit material remains labeled historical rather than rewritten.
