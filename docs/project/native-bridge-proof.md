# Bounded proof: resident process → intended desktop thread → resident result

Status: **PREPARED_DESIGN_ONLY / NO_EXECUTION_AUTHORIZED**. P06 reports a queue command in installed
alpha CLI help and a failed default control connection. A daemon-version failure is not a failed
queue dispatch or proof that no internal desktop server exists. Do not infer a repair from an error
number. No broad re-audit, service install or live coursework is needed for the first proof.

## Gate 0 — choose an unchanged runtime window
The desktop reports restart_required. Ask the user to complete any desired supported restart after
saving active work, or explicitly choose a documented unchanged-runtime probe. Do not terminate
processes, restart Windows, install/downgrade software, delete sockets/locks, inspect session DBs,
change firewall settings or expose ports. After any approved change, re-read exact binary path,
CLI/Desktop versions, auth category and documented transport, not only the old cache directory.

## Gate 1 — prepare an exact isolated target and return route
Prepare a one-page proposal containing runtime identity, route, new disposable native thread/project
or already-designated disposable target, verified root, effective model/effort, tools and permission
profile, exact bounded prompt, output destination, timeout, terminal-result channel and cancellation
semantics. Native thread creation and its history/logs are writes and must be covered by approval.
Never borrow the real PS02 conversation for a proof or take its observed UUID as permission.

Use the least-capable test settings: synthetic content only, no coursework sources, no model tools
required, restricted filesystem/network/connector effects, human-visible approval. A no-tools prompt
is a request, not an enforcement mechanism. Verify actual capabilities and approvals; if enforcement
cannot be established, stop. A filesystem read-only mode does not by itself constrain every MCP or
app tool. Existing broad user defaults must not be assumed safe. Never change global defaults just
to make one test work. Per-turn App Server overrides can persist for later turns; use a disposable
thread instead of experimenting with a real course's configuration.

Preferred first candidate: the reported `codex queue --thread ... --message ...` on that installed
version, **only if** its verified route and preconfigured target meet the safety requirements. Do
not invent per-turn queue flags. The sender and terminal-result readback must both be usable by an
ordinary PC process. Native agent tools can cross-check independently, but cannot stand in for a
missing companion return interface. `exec`/`exec resume` is a separately owned worker unless exact
native compatibility is observed. An independent stdio App Server with a similar thread store is
not automatically the resident desktop connection. Experimental routes need explicit consent.

Request one approval of the concrete proposal. Until approved, no thread creation, message queueing,
server bootstrapping or proof files written into courses. Use conversation output/attachments for
preparation. Report unavailable capabilities precisely rather than searching private runtime state.

## Gate 2 — one local synthetic roundtrip, after approval
Generate a unique request ID and nonce in the approved local proof area, outside every course root.
Use one synthetic prompt, for example asking 19 + 23 while returning the given request ID/nonce.
The expected numeric answer is 42; no actual learner evidence, source, grading or canonical write
is involved. Keep the exact prepared prompt and submitted bytes/digest, not hidden model reasoning.

Record submission transport identity, target project/thread, effective permissions and observed
turn/item IDs. Accept terminal evidence and the matching bounded reply only from the approved
return interface. A command exit code, queue acknowledgement, model self-report or early partial
message is not completion. The host verifies nonce/result and records it; the model need not write
a file. Native platform history and the proof report are the only enumerated output effects.

If queue accepts work but return monitoring fails, classify **ACCEPTED_OUTCOME_UNKNOWN** and inspect
the original identified run through the supported interface; do not resubmit. A failed/default
control probe prevents claims of a reliable route but must not be misreported as queue rejection.
If queue reaches a new CLI worker but not the intended desktop target, report **SEPARATE_WORKER_ONLY**.
A native-agent-only observation is **NATIVE_OBSERVED_PROCESS_RETURN_UNPROVEN**, not end-to-end PASS.

## Gate 3 — later tests, not automatically authorized by Gate 2
After the exact local bridge is demonstrated, obtain approval for small additional tests:
- Fake duplicate/out-of-order/late input through the proposed supervisor: one accepted identity;
  a duplicate may not induce another inference simply because the native tool lacks idempotency.
- Active-turn conflict and interruption: request/generation fencing, expected native identities,
  terminal status; interrupt acknowledgement alone is insufficient.
- Safe approval pending/decline: preserve user control, no automated acceptForSession/bypass.
- One authorized second-device Drive bundle to one proof folder: same content/digest at the PC
  and result seen on that second device. Local equality does not establish global cloud currency.
- Fixture-only full snapshot and learning save, after explicit global-root isolation. No real
  learner records, shared mappings, schedules or source publications touched.

Limit the first proof to one request and one observed terminal result. No permanent daemon,
autostart, polling loop, full regression marathon, forced cancellation demo, or bulk media job.
Proposed timeout 120 seconds may be adjusted in the approved test card; timeout is not automatic
failure-safe retry. Installed packages are not authorization to transcribe recordings or spend.

## Evidence required and stop point
Return a short gate outcome, exact tested surface/version, actual request/thread/turn/result IDs,
effective safety evidence, output hash, start/stop times, permission decisions, preservation scope
and remaining unknowns. Do not inspect private credentials, native SQLite/session files, or hidden
reasoning. Hash comparisons cover the named files only, not a universal proof no writes occurred.
The first PASS means **one observed local route**, not cross-device operation, production reliability,
complete source tools, all-course bindings, image/voice capability, canonical saves or unlimited quota.

Public protocol references and their installation boundary are in the [research addendum](../research/native-bridge-recheck-2026-10-03.md).

## Avoid needless repeated permission steps
The prepared card may enumerate creating exactly one disposable project/thread via a supported
interface under a named approved proof root; actual IDs can then be returned by that creation
operation. Verify the returned identity before sending. This exact creation and its native history
writes must be in the approved card, not done during preparation. No additional approval is needed
merely to repeat an already approved step unchanged, but any different target, new capability or
broader access must stop for a revised decision. Provider inference uses the existing managed
sign-in; “no tool/network actions” excludes unapproved side-effecting tools, not the necessary
provider inference transport. Never substitute an agent's claim of its own identity for native data.
