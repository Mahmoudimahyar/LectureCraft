# Required NATIVE_SETUP_REPORT.md

Produce `.local/reports/NATIVE_SETUP_REPORT.md` early and update at completion. The reports supplied
by the user are dated installation evidence, not a permission to contact any remembered thread.
A local Codex desktop project, ChatGPT Work/cloud chat, Claude Code development session, and
ChatGPT-backed CLI authentication are different identities. Keep requested native continuity.

For every proposed change, record: product and exact observed version; inspected current value or
NOT_OBSERVED; required capability; exact setting/menu/command only when verified for that version;
old→proposed value; reason; filesystem/account/data effect; source URL or inspected help; user-only
step; rollback; actual test still required. Never inspect or copy tokens, cookies or authentication files. Do not invent a universal 'watch Markdown' toggle.

Required sections:
1. Development environment versus target tutoring environment. Claude codes; it is not silently
   made the tutor just because its test doubles return text.
2. Exact canonical root/project/thread binding and desired native capabilities. No global 'latest'.
3. Effective auth category (no secrets), tools, sandbox and approvals. Broad defaults must not be
   assumed safe or inherited to a test thread. Never recommend danger-full-access as the shortcut.
4. Independent resident-process submission AND terminal-result retrieval. Queue help/accepted
   return, native internal read_thread availability, and completion are separate facts.
5. Pending updates/restarts and observed errors. An old Windows 10050 control-socket failure does
   not establish a cause; do not delete sockets, replace daemons or restart during local build.
6. Supported disposable proof procedure after authorization; no existing course chat as sandbox.
7. Independent Drive OAuth/client origins/scopes, desktop mount vs cloud bytes, and device pairing.
8. Pinned existing writer identity, full-sidecar verification and globals that make fixtures unsafe.
9. Smallest actionable checklist, grouped into mandatory manual activation, optional enhancements,
   and unsupported/unverified features. List no guessed credentials or paid inference fallbacks.

The build can finish local code without making these changes. Real activation still needs the
correct permissions and proof. No background watcher is installed by this kit.
